## 生效流程

1. **图片分析与方案规划**：复用当前分析模型（现在可用DeepSeek，也可换其他模型），在同一次请求中提取每个方案的 `feltProfile`。只选择存在或明确计划的部件与混合材质；返回缺失时用方案描述兜底。
2. **初次生图、单张重试**：`workflow.dispatchImage` 是统一入口；按任务选择改款、二维转立体、其他材质转换要求，附加参考图角色、部件规则和摄影设置。
3. **精修**：参考当前选中图片的部件和摄影快照，加入最新修改要求；保留父子关系、未指定改变的细节。切换图片或重开项目后界面跟随当前版本，不自动退回最初背景。
4. **主设计及多角度**：设定卡继续保存可见细节与未知结构，使用主图、已确认角度和角度参考；按实际视角保持形象、纹样和连接位置。未知背面仍由原有补充/确认流程处理。
5. **实际模型派发**：`generation-runtime.ts` 按实际渠道和上游模型选择GPT Image、Gemini、Grok或通用适配，在原始任务上重新组装一份规则，不叠加旧规则块。返回实际快照用于图片档案和调试查看。
6. **图片检查**：在原有检查调用内增加部件材质、摄影和构图目标；允许的背景与取景变化不当作身份错误。结果是视觉建议，不是像素测量或实物材料鉴定。
7. **保存与导出**：新增字段可选，兼容已有项目schema；新图导出增加 `visual-rules.json`，现有图、文案、商品JSON和版本链继续保留。

普通画布、PPT及高级工具没有 `feltContext` 的请求保持原有逻辑。视觉材质规则不作为文案中的实物成分证明；标题与商品文案继续依赖原有已确认商品资料。

## 优先级与摄影控件

顺序为：用户明确指令 → 锁定的主体特征 → 用户选择的摄影/构图 → 材质默认规则 → 自动场景推荐。精修最新指令只覆盖所指定的变化，其他既有要求保持。自由文字完整进入请求；常用“保留背景”“仅修改材质”、明确主体百分比和画幅比例会同步到有效设置。自然语言解析只覆盖常见明确表达，复杂表达由模型结合原文理解。

“摄影与构图”默认折叠，提供五个背景：原背景、自然木桌、家居、主题生活场景、白底摄影棚；可独立勾选保留背景。构图分为保留原图和使用新占比；占比有45%、60%、75%、85%预设，也可在35%至90%滑动。画幅比例独立控制，沿用既有模型尺寸接口。

改款新项目默认自然木桌、60%、1:1。转换任务与旧项目编辑默认保留背景和构图；用户可以主动改成商品摄影设置。仅材质要求不会强制木桌。主题生活场景按商品实际主题布置，无节庆信息时不强加节日装饰。白底不会添加木桌。

占比指整体外接范围占图片高度，不是头身比例。宽动物和组合优先完整入镜；占比允许降低以免裁切。指定值是模型构图目标，不能保证每次精确执行。尺寸字段仍按各渠道已有能力转换，供应商只支持固定尺寸时会使用现有近似映射。

## 模型适配与维护

GPT Image使用分段保留要求、部件细节和完整约束；Gemini/Grok使用较短且前置的材质规则；未知模型使用通用结构。订阅渠道标识优先于员工看到的模型别名。所有适配继续走原有模型请求接口，不增加自动模型调用或自动循环重试。

新增部件时更新 `types.ts`、部件映射及枚举校验；模型识别失败时规则仍以“已存在/明确请求”为条件，不能因示例出现而添加器官。新增适配更新 `feltAdapter` 与对应组装分支，再覆盖实际出站请求测试。

- `examples/natural-tabletop-60.txt`：蓝帽人物二维转立体，自然木桌、60%、1:1。
