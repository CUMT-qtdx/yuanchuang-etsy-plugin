# 首次侧背面材质连续性

版本：`1.15.4-etsy.36`（保留 `.35` 诊断记录，模型选择和左右参考规则已更新）。目标是正常点击生成时直接提高侧面/背面的材质接近度，“只修材质”保留为后备；没有自动追加一轮修图来冒充首次成功。

## 本次真实诊断结论

`.34`确实把主图材质局部用于首次生成，不只是增加修复按钮。实际用户记录也证明首次侧背面包含主图和两处局部。结果仍粗化，不能将“请求里有规则/测试通过”视为视觉问题已解决。

使用同一张批准主图，通过用户已经配置的图片通道进行了18次真实请求，全部另存审计目录，未改商品图。13次GPT测试覆盖去局部、精简/摄影优先/紧实毡面措辞、high质量、同次三视图、原参考辅助、输入尺度等，没有稳定的材质优势；5次Grok测试（含正式组装器输出）在本样本的身体细密短绒方面更接近主图。该结论仅限实际样本，不能推广为所有商品Grok必定更好。

Grok样本仍有帽檐分区简化、姿态/小细节偏差风险；左右视角本次不作为已修复问题。实际输出分辨率也可能与主图不同，这是模型返回尺寸，不宣称像素一致。

## 正常生成入口的变化

- 新增独立“侧面 / 背面模型”选择，仅影响左侧、右侧和背面。优先尊重当前主设计已保存的选择；未保存时跟随当前图片模型，不再自动预选Grok。选择立即随主设计保存，失败时回滚；重开项目后保留。界面显示实际选择，用户可改回。不会修改全局图片模型、分析模型、账号或主图。
- 首次侧背面和对应“重做”使用 `[hero_surface_continuity_v1_0]`，第一张外观参考是完整定稿主图；左右侧面另附一张仅表示方向的示意图，背面仍只输入主图。减少容易诱发纹理重绘的材质长文，不把独立局部或其他AI角度叠加为生成参考。用户固定细节与人工编辑的设定卡仍有优先约束。
- 改用照片编辑式指令，直接保持原表面、正常摄影尺度、自然短纤维及原始明暗层次；禁止额外纹理增强/锐化。材质不同的部件仍按原图保留。
- 正面和斜侧面的原有规则分支及上方模型选择保留。材质局部继续用于检查和后备修复，已保存样本不删除。
- 单个角度仍1次生图＋原有1次检查，没有隐藏的二次材质修复、候选挑选或自动重试。API调用失败按既有错误状态处理，不静默转模型。
- “只修材质”仍以当前角度为父图，带上主图及局部，保留原图；“重做”侧背面则直接回到完整主图生成，保存新的父子版本。

顺便补齐Grok订阅渠道的画幅参数转发：`1:1`等已支持比例直接转发，像素尺寸仍使用原映射。没有改动其他渠道。

## 主要文件和核对

`src/etsy/multi-view/surface-continuity-v1.ts`：首次照片式规则、侧背面范围与模型选择函数。

`src/etsy/workflow.ts`、`routes.ts`、`types.ts`：按角度路由、持久化该组模型、直接参考来源、重做分支。

`src/etsy/felt/composer.ts`：运行时保留专用模块，不重新拼入通用材质/创意任务。

`src/client/FinalDesignPanel.tsx`：独立模型入口；侧背面首次生成不再依赖额外材质取样分析。

新图Prompt应包含 `hero_surface_continuity_v1_0`，`references`在背面只有主图，在左右侧面包含主图和方向示意图，记录的model应与面板侧背面选择一致。`.34`旧图不补标、不自动重画。

工程测试见 `scripts/first-pass-material.test.mjs` 和现有Chrome流程：核对模型分工、单次请求、明确主图参考、正常生成/重做/修复三种路径、保持人工锁定、模型选择恢复、原数据不变。视觉判断单独记录，不能以单元测试替代真实图片验收。

`.36` 的左右方向约定、检查与 GPT 验证见 [方向模块说明](view-direction-v1.md)。历史 Grok 样本结论不作为当前默认模型选择依据。
