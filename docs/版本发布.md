# 单文件版本发布

员工始终从 [最新版本](https://github.com/CUMT-qtdx/yuanchuang-etsy-plugin/releases/latest) 下载唯一的 EXE。

下载完成后，退出 DSH，双击 EXE 并点「安装 / 更新」。项目、图片和渠道设置沿用该电脑自己的数据。

## 发布一个新版本

1. 在 `package.json` 和 `src/protocol.ts` 中更新版本号，例如 `2.0.0-etsy.9`。
2. 完成当前改动的验证，提交并推送源码。
3. 创建并推送同名标签 `v2.0.0-etsy.9`。

GitHub Actions 会构建插件、将依赖装进 EXE、校验真实 EXE 入口，再向 Releases 发布一个附件。构建失败时不会创建新的公开发布。

也可从 GitHub 的 Actions 页面选择「发布 Windows 单文件安装器」，点击「Run workflow」发布所选分支中的版本。

## 本机打包

在 Windows 项目目录运行：

```powershell
pnpm install --frozen-lockfile --ignore-scripts
pnpm run build
pnpm run release:exe
pnpm run test:installer
```

结果在 `out/windows-installer/Update-Yuanchuang-Etsy-版本号.exe`。`installer-manifest.json` 是维护者的构建记录，发布页只上传 EXE。

如果某版本已先通过本机安装验收并上传一个 EXE，工作流重跑会保留该附件，不覆盖成另一份重新构建的文件，也不追加第二个附件。发布时应核对桌面文件与 GitHub 下载附件的 SHA-256 一致。

## 联网和安装

发布到 GitHub 与安装时是否联网是两个环节。员工需要联网下载新版 EXE；EXE 已包含该版本的插件和运行依赖，因此安装过程无需访问 npm。

此 EXE 安装或更新的是 DSH 插件。首次使用的电脑需先安装并打开过 DSH 主程序。安装器会自动定位主程序，识别不到时可手动选择。

## Windows 安全提示

当前安装器没有商业代码签名。GitHub 托管不会为下载的 EXE 自动添加受信任的发布者签名；Windows 仍可能提示未知应用或按设备策略拦截。

面向更多电脑长期分发时，应为后续 EXE 配置受信任的 Authenticode 代码签名。自签名证书不能代替公开受信任的签名。签名也不等于每个新文件立即获得 SmartScreen 信誉。

参考：[微软的 SmartScreen 分发说明](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation)。
